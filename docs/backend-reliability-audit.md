# 后端可靠性复查

本轮聚焦 Agent 的任务生命周期、审批恢复和 Daemon 文件接口。以下问题已修复；这是针对性的可靠性检查，不能代表所有后端模块均无缺陷。

| 问题 | 原来的影响 | 修复 |
| --- | --- | --- |
| 上传失败清理目标文件 | 上传先截断已有文件，断线或超限后还会删除原文件 | 文本、Base64、流式上传均先写暂存文件，成功后发布；失败只清理暂存文件 |
| 上传并发覆盖 | 两个禁止覆盖的请求都通过存在性检查，互相覆盖 | 发布阶段执行排他创建；冲突返回 409 |
| Multipart 静默截断 | 解析器达到限额后正常结束，残缺文件可能被当成成功 | 检查 truncated 标记，拒绝发布并返回 413 |
| 追加指示遗漏 | 模型生成最终回复期间收到的指示不被处理；同批后续修改继续按旧要求执行 | 模型返回和每个工具之间检查新指示，跳过过时调用并重新规划；收尾阶段关闭追加入口，避免接受后丢失 |
| 取消漏记结果 | 文件刚写完就取消，恢复记录中没有该成功操作 | 先保存已返回的工具结果，再停止后续工具 |
| 等待状态假完成 | 等审批、等回答都显示完成，可能被“清理已结束任务”删除 | 增加 pending_input 状态，按真实结果分类，保留等待任务；重连等待任务时结束当前响应流 |
| 长任务和工作区恢复 | 超过一小时的运行任务从列表消失；当前工作区无任务时可能接上其他工作区 | 活跃/等待任务不按已结束任务 TTL 隐藏；显式工作区查询严格匹配，包括无实例上下文 |
| 审批重复执行 | 审批、拒绝并发请求可越过异步准备阶段；工具成功但审计失败后，重试可能再次修改 | 三种决策共用互斥锁；审计失败后复用已保存结果并补审计；恢复原任务的状态、进度和取消入口 |
| 回答或拒绝丢失 | 后续模型无法运行时，磁盘恢复记录仍停留在等待用户的调用 | 先保存确认的决策，再检查后续调用条件；恢复记录保留回答/拒绝结果 |
| 读取触发建目录 | 查询不存在的文件也会创建父目录；链接越界检查在建目录之后 | 读取不创建文件父目录；写入先核验最近已有祖先的真实路径，再创建父目录 |
| 关闭前端后结果失联 | 后台结果依赖页面上传历史，页面关闭后其他设备无法读取完整结果 | Agent 执行 Promise 归任务所有；服务端保存开始记录和最终结果；SSE 断开仅移除订阅 |
| 网络回退启动两次 | 流式请求失败后再请求普通接口，可能启动第二个 Agent | 两个入口共用任务运行器，用 clientRequestId 去重；检查与认领任务之间不让出执行权 |
| 设备互相中断 | 同一工作区的新请求自动取消先前任务 | 同用户同工作区已有运行或等待任务时返回 409；取消后仍在收尾的执行继续占用工作区 |
| 审批执行阶段不可见 | 命令执行完成后才恢复任务状态，期间无法观察或取消 | 执行命令之前恢复同一个任务；审批请求断开不会取消任务；明确取消会停止后续模型调用并保留已完成操作 |
| 清理绕过执行互斥 | 刚取消的命令尚未退出，其他设备删除或清理任务后可启动冲突工作 | 执行和决策 Promise 收尾之前保留任务；拒绝提前删除，不按 TTL 或清理操作移除 |
| 跨设备旧记录覆盖 | 多个上传无版本校验，较晚到达的旧消息覆盖后台结果 | 数据库 updatedAt 条件更新和单对话写入队列；过期写入返回 409，页面刷新后采用服务端版本 |
| 重连输出重复或丢失 | 部分文本与整个缓冲区重复拼接；React 消息 ID 在异步 updater 内确定 | 稳定的用户/回复 ID，重放前重置临时输出；终态只发送一次；切换工作区清理本地订阅并恢复忙碌状态 |
| 多设备页面状态滞后 | 历史仅初始化拉取，乱序请求或本机时钟影响更新 | 可见页面定时同步，聚焦/联网立即刷新；串行请求与写入队列只接受更新的服务端版本 |
| 删除记录重新出现 | 删除当前对话时又保存旧对话；服务器拒绝删除却在本地隐藏 | 删除成功后再移除本地记录，重置时不保存被删对话；运行和等待中的对话受保护 |

```sh
npm run check
npm run build
```

测试源码和测试脚本已于 2026-10-12 按项目清理要求移除，以上保留类型检查与构建命令。历史测试使用隔离目录中的真实文件操作、实际文件路由处理器、实际审批/回答处理流程，以及模拟模型和数据库。不会调用付费模型或改动真实数据库。真实目录链接测试在禁止创建链接的 Windows 沙箱中跳过，另有模拟真实路径解析的测试验证检查先于目录创建。

## 运行与同步边界

- 关闭浏览器、页面或聊天面板后，Panel 进程保持运行时 Agent 继续执行。停止服务器、电脑休眠或重启不是同一种情况：进程停止后不会自动继续执行命令，已有磁盘检查点和等待决定可用于恢复。
- 多设备需要连接同一个 Panel 并登录同一账户。任务和审批互斥是单进程实现；本次没有加入多 Panel 副本之间的分布式执行锁。
- 运行进度用 SSE 同步；页面在没有订阅时每 4 秒检查任务，可见页面每 5 秒同步历史，并在聚焦、联网、显示页面时刷新。完整结果由服务端保存；历史同步失败保留待写结果，每 60 秒重试。已执行的命令不会因此被标成失败或自动重放。待写结果的重试队列保存在进程内存，持续故障期间仍需保持 Panel 运行。
- 已结束任务的内存重连记录保留 1 小时，历史记录保存在数据库；运行、等待决定和历史保存失败待重试的任务不按已结束任务 TTL 清理。重复请求去重依赖仍保留的任务记录。
- 未在两台真实设备与付费模型上进行端到端验收，也未完成部署环境的重启验收。路径检查不能消除外部进程在检查与操作之间替换目录链接的竞争；排他复制回退不具有重命名式的瞬时完整可见性。

更新需要部署新构建并重启 Panel、Daemon，网页资源也需更新。本次不涉及数据库结构变更。
