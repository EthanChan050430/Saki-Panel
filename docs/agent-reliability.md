## 已定位的问题与修复

| 原实现 | 修改后 |
| --- | --- |
| 提示词要求改完代码诊断一次就停止，且禁止测试套件 | 要求推进整个任务，在适当节点验证并修复失败；允许运行针对性测试、构建。 |
| 默认 40 行、最多 120 行；大文件无 startLine 时返回拦截信息；连续翻页被提示阻止 | 默认从第 1 行读 200 行，可请求 2000 行；按实际输出大小截断并返回准确续读行号；允许必要的连续读取。 |
| 文件窗口先截成 4000 字符，送入模型时再截成 3600 字符，行号仍按原窗口报告 | 以完整行组织最多约 24000 字符的窗口；预留额外空间给路径、行号和续读信息；特别长的单行明确标记截断。 |
| 修改后的读取可能使用旧内存副本或跨调用缓存 | readFile 重新从 Daemon 获取内容，文件修改后清理重复调用计数。 |
| writeFile 只能创建，既不能分块追加也不能更新已有文件 | 默认创建或更新完整内容；已有文件要求读取及写入权限并保留检查点和差异；相同内容直接成功，overwrite=false 可限制仅新建；支持 append=true 分块追加。 |
| 把模型的上下文 @@ 直接交给只理解数字行号的 unified diff 解析器 | 独立解析新增、更新、删除和上下文 hunk；支持多 hunk、CRLF 和文件末尾定位；上下文不唯一时拒绝猜测。 |
| 新文件检查与写入分离，可能覆盖期间被其他写入者创建的文件 | createOnly 在 Daemon 执行时使用排他创建；覆盖写入先生成并刷新临时文件，再重命名发布。 |
| 达到 80 轮后用“已完成修改”生成兜底总结 | 默认上限提高至 400；到达上限明确返回未完成状态、重试入口及剩余清单。 |
| 仅 respond 工具检查旧的诊断记录，普通文本结束可以绕过 | 两个入口都检查；必须检查最后一次修改之后的验证；验证失败要求修复或说明阻塞。 |
| 多种卡住状态没有 Retry，容易被任务列表标为成功 | 轮次耗尽、无效输出、重复、无进展和工具反复失败都返回 retry 信息。 |
| 执行器抛出的传输或审计异常可能直接中断整个循环 | 转成失败观察返回模型，明确操作结果尚未确认，要求检查目标后再重试修改。 |
| 模型达到输出 token 上限时，工具参数可能不完整 | 在 OpenAI 兼容、Anthropic、Ollama 原生工具响应中识别输出截断；阻止整轮工具执行，提示改用较小补丁或追加块重试。 |
| 会话恢复状态只保存在内存、任务结束时才保存 | 修改执行前保存调用意图，每个处理后的工具结果以及任务结束时保存状态；启动时重新加载。 |

## 接口与边界

```js
readFile({ path: "src/app.ts" });
readFile({ path: "src/app.ts", startLine: 201, lineCount: 500 });
writeFile({ path: "src/new.ts", content: "完整代码" });
writeFile({ path: "src/create-only.ts", content: "仅新建", overwrite: false });
writeFile({ path: "src/new.ts", content: "下一段代码", append: true });
writeFile({ path: "src/new.ts", content: "完整替换内容", overwrite: true });
```

- 写入没有行数限制。原有在线文本文件 1 MiB 大小限制仍然适用，分块追加后的文件同样受此大小限制约束。
- 400 轮是单次运行的上限，不代表无限后台执行；达到上限后可通过 Retry 或“继续”续接。
- 会话文件位于 Panel 数据目录的 `saki-sessions`，按用户和实例隔离；同一用户、同一实例保存最近会话，恢复有效期为 24 小时。服务重启后加载进度，需要用户触发继续，不会自动重放修改。
- 进程可能恰好在文件已修改、结果尚未记录之间退出。恢复时未配对的调用标为未确认，模型必须检查实际文件；不承诺修改恰好执行一次。
- 多文件块补丁支持 Add/Update/Delete、`@@`、可选定位锚点和 `*** End of File`。移动文件使用已有 renamePath 工具；此解析器不是官方完整实现。
- 不支持硬链接的 Windows 沙箱或文件系统使用排他复制创建新文件，防止覆盖仍有效，但此回退不提供与重命名相同的完整文件瞬时可见性。
- 清单和检查结果用于阻止明显的提前结束，不能证明未写入清单的所有用户需求都已满足。

## 实例启停优先使用面板接口

- Agent 优先通过 `describeInstance` 确认目标、状态及启停配置，再调用面板的 `instanceAction`：已停止或崩溃的实例用 `start`，运行中的实例需要重启时用 `restart`。省略 `instanceId` 时操作当前实例。
- 普通编码任务也提供 `describeInstance`、`instanceAction`、`instanceLogs`，模型工具数量裁剪会优先保留这条路径。普通提示词、精简提示词和自定义提示词均有此规则。
- 不默认采用“查端口/PID → 结束进程 → 在独立终端启动”的方式。接口调用后结合日志和实例状态验证；接口返回成功仅表示操作已请求，不能据此断言服务健康。
- 接口失败时先检查错误、实例状态和日志。仅在用户明确指定终端方式，或确认面板接口不可用、不能满足操作时，才考虑终端恢复；不得绕过权限拒绝或审批拒绝。
- 此调整是工具选择和提示引导，不会把所有终端命令硬性封禁。原有账号权限、审批、Plan、聊天、研究和 Watch 模式限制仍然有效。
