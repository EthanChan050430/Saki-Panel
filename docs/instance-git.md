# 实例 Git 管理

在实例的「文件管理」中切换到「Git」。仓库位于实例工作目录，实际操作在实例所在的守护进程节点上执行。

## 使用

1. 没有仓库时，点击「创建 Git 仓库」，初始分支为 `main`。
2. 在「排除规则」中选择文件或文件夹，也可以编辑 `.gitignore`。保存时保留磁盘文件；已跟踪的所选路径会从暂存区取消跟踪，需要再提交这一变更。
3. 在「工作区」勾选需要提交的文件。点击文件名可预览差异，填写提交说明及提交者后提交。提交者信息保存在当前仓库的本地配置中。
4. 「Saki 生成草稿」使用面板当前配置的模型，总结所选变更，填入可编辑的提交标题、正文与 Markdown Issue 草稿。Issue 可复制到代码托管平台；此功能不会发布远程 Issue。
5. 「提交记录」分页显示所有已有本地和远程引用可达的提交，包含分支连线、合并节点、作者、时间与代码差异。合并提交的差异相对于第一个父提交；搜索作用于已加载记录。

文件管理中选择项目后，也可点击「将所选排除 Git」直接进入排除规则。

## 运行要求与权限

- 守护进程节点需要安装 Git。守护进程 Docker 镜像已包含 Git。
- 查看仓库、提交记录和差异需要实例的 `file.read` 权限；初始化、提交和修改排除规则需要 `file.write` 权限。
- Saki 草稿还需要 `saki.chat` 或 `saki.agent` 权限，并沿用现有积分规则。
- 支持以实例工作目录为根的普通仓库。链接工作树、外部 Git 元数据及符号链接路径暂不支持；实例目录属于上级仓库时不会创建嵌套仓库。
- 提交保留其他文件的暂存内容，通过独立索引创建所选文件的提交，并以原 HEAD 为条件原子更新引用。正在合并、变基或存在冲突时，需要先在终端完成这些操作。
- 界面不执行 Git hooks、外部差异转换或仓库自定义过滤程序。使用 Git LFS 等过滤器的所选文件会拒绝提交，需在终端中提交以保留存储格式。
- 排除规则有并发修改检测。手写 `.gitignore` 规则仅影响未跟踪文件；取消已跟踪文件的跟踪时请通过选择器明确选择路径。

## 远程节点更新

Git 接口由实例所属节点的守护进程提供。仅更新面板或前端，无法让旧节点获得新接口。

如果看到 `Route GET:/api/instances/.../git/status ... not found`，说明节点尚未注册 Git 接口。面板会将这类错误显示为需要更新守护进程，并注明节点名称。

将包含此功能的代码或构建产物部署到对应节点后，按原部署方式重启守护进程。源码部署需在项目根目录执行：

```sh
npm run build -w @webops/shared
npm run build -w @webops/daemon
```

然后重启实际运行的 daemon 服务（服务名以部署配置为准）。Docker 部署需重新构建或使用包含此功能的镜像并重建 daemon 容器；独立可执行文件部署需替换为包含此功能的新版程序后重启。保留节点的 identity、工作目录和现有实例数据。守护进程完成更新后，在 Git 页点击刷新即可重新检测。

## 验证

```sh
npm run test:git -w @webops/daemon
npm run test:git -w @webops/panel
npm run check
npm run build
```

Git 测试仅在系统临时目录创建测试仓库，覆盖首次提交、分页、分支与合并、重命名、删除、排除文件、特殊文件名、无关暂存内容保留及实例路径边界，同时检查正式守护进程的全部 Git 路由及鉴权。
