# Agent 权限模式（2026-10-11）

后续安全约束见 [Agent 账号边界与外部资源读取](agent-resource-security.md)：所有模式都受账号与实例授权限制；外部文件始终单次审批。当前未实现 OS 进程隔离，宿主机执行及计划任务定义仅允许 `super_admin`，因此下文的终端自动放行规则只在通过该身份检查后适用。

此前 `ask` 拦截几乎全部修改操作，`acceptEdits` 也会拦截每一条终端命令。现在按操作风险决定是否请求批准，常规工作不再逐项打断。

| 界面选项 | 行为 |
| --- | --- |
| 请求批准 | 工作区普通文件读写、已识别的本地读取/构建/测试直接执行。显式终端联网、外部/敏感路径和风险操作请求批准。 |
| 帮我批准（默认） | 在上述基础上，规则审查自动放行常规依赖安装、已识别的检查工具下载和简单无认证网页读取；检测到风险则请求批准。 |
| 完全访问权限 | 常规操作无需逐项审批；外部文件仍需单次审批。仍执行账号权限、实例访问限制、文件路径检查和严重危险命令的硬性限制。 |
| 仅规划 | 只读工具与已识别的只读命令；构建、测试和格式化即使风险低也不能执行。 |

交互语义参考权限与沙箱以及自动化审查规范。保留已有存储值 `ask`、`acceptEdits`、`bypassPermissions`、`plan`，已有会话与多设备同步无需迁移。前端只调整权限选项的文字和顺序，以及相应英文翻译；陪伴画面、玻璃输入框和消息区以外的布局保持原样。

## 审批判断

- `git status/diff/log`、`rg`、`Get-Content`、`npm run check/build/test`、常见 Python/Rust/Go/.NET 检查直接执行。支持相对路径切换与简单命令组合，每一段都必须通过审查。
- `npm ci/install`、`pnpm add`、已识别的 `npx` 检查工具、简单无认证 `curl`：请求批准模式询问，帮我批准模式自动放行。`npx --no-install` 的已识别检查工具按本地操作处理。
- 删除命令、`deletePath`、包含删除文件的补丁、Git 历史/远端变更、全局安装、自定义 registry、外部/敏感路径、未知程序、内联脚本、重定向和难以判定的 shell 语法请求批准。
- 原始终端输入、命令携带 stdin、实例生命周期/设置/计划任务变更继续请求批准。命令审批预览包含实际触发原因与 stdin 摘要。
- 专用搜索/浏览工具继续使用各自的工具权限与公共地址校验，不被终端联网审批反复打断。
- 完全访问权限与手动批准都不能绕过账号权限、只读规划模式或已有硬性安全检查。

### 2026-10-18：减少误审批与审批续接

- 修正 `rg -t`、`ls -d` 等读取选项被误当作上传或执行参数的问题。补充 `find`、受限的 `sed -n` 行读取、进程/磁盘/内存查询、Windows 目录开关和只读 Git 目录选项。
- 已确认 POSIX 节点允许引号中的中文正则、`|` 和 HTML 字符；引号外的命令组合仍逐段检查。未知终端或 Windows 不假定 POSIX 引号语义。删除、输出覆盖、命令替换、未知脚本、敏感与越界路径仍不会自动放行。
- POSIX 的 `>/dev/null`、`2>/dev/null`、`&>/dev/null` 和标准错误合并按丢弃输出处理，不再误报越界；该特例不开放 `/dev` 目录，也不允许从 `/dev/null` 读取或重定向到其他工作区外文件。
- 命令风险与工作区检查共用参数识别：Windows 的 `/a:-d`、`/o:n` 等开关，以及 `rg`、`grep`、`findstr`、`Select-String`、`find` 中已识别的搜索文本不再冒充文件路径。搜索 `shutdown`、`/api/`、`.env` 或打印危险命令示例不会因此触发硬拦截。实际文件参数、`-f` 模式文件、忽略文件与辅助程序继续检查；未引用的通配符不享受文本特例，未知参数无法确定角色时保持保守检查。
- `npm/pnpm/yarn run` 不带脚本名时按列出脚本处理。终端安全检查使用完整输入并保留换行，预览截断和换行显示转义只用于界面与审计，不影响真实命令检查。
- Agent 初始任务保留最近的聊天历史。审批和问答恢复沿用同一份结构化对话、原始目标、清单、工具结果与提供方状态；已执行动作只作为结果加入，避免重新执行。旧检查点缺少结构化记录时，从已确认动作恢复进度。
- 等待审批不再清空工具缓存；完成文件修改只失效相关文件和目录观察，保留其他文件、其他工作区以及技能/网页参考。影响范围无法确认的终端操作仍失效该工作区观察。权限校验继续先于缓存命中。
- `readFile` 复用任务内最近的有效结果；文件修改后自动失效，显式 `refresh=true` 可强制重新读取。文件和参考缓存保留五分钟有效期；实例/Git 状态、环境与诊断结果仅保留五秒，避免把旧状态当作当前证据。

### 主动询问缺失信息

- Agent、聊天与规划模式均提供 `askUser`，收缩工具列表时优先保留询问工具。目标、验收标准、目标实例或必要接口资料仍不明确且无法从上下文查清时，先询问用户；常规实现选择与可自行检查的事实继续自主处理。
- 询问会显示“需要你的回答”卡片，支持选项、自由填写或跳过。兼容模型只用简短明确的文字直接请求澄清的情况，将识别出的请求转为同一询问工具；普通解释、示例和泛泛的不确定表述不会因此自动变成问题。
- 同批工具调用包含询问时，只执行该问题，其余调用留待回答后重新规划；回答续接保留原始目标、提供方状态和有效工具结果。跳过不代表审批，也不能据此编造目标或用户决策；没有安全默认值时说明仍缺少什么。
- 后台 watch 与研究子任务保持原来的工具边界，不通过兼容处理擅自创建交互式等待。

复用终端时，每次命令先回到实例工作区或显式指定的相对子目录，切换失败则整段不执行。守护进程返回实际终端类型，分别处理 PowerShell、cmd、POSIX 的目录引用；旧节点缺少类型时按节点信息回退。PowerShell 还清除上次原生命令的退出码，避免后续 cmdlet 继承旧的失败结果。

## 实现边界

这是后端规则审查，不是独立的外部安全审查模型，也不是操作系统级沙箱。常规构建/测试会执行项目代码，依赖安装可能执行生命周期脚本；它们的子进程、依赖配置、符号链接、shell 函数和继承环境不能靠命令文字分析实现强制文件/网络隔离。只支持当前面板授权实例范围，完全访问权限不意味着开放宿主机所有文件。文件工具的外部与敏感路径限制继续生效。
