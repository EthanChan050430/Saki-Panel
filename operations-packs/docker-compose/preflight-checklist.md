# Docker Compose 上线前检查表

此清单用于首次部署、升级前审批和事故修复后的复核。它不下载镜像、不改写配置，也不代替实际备份恢复演练。

## 配置与边界

- [ ] 已确认唯一的 Compose 根目录与 `-f` 文件顺序。
- [ ] `docker compose config -q` 已通过；未解析的变量和 profile 已被处理。
- [ ] 每个镜像都有可追溯 tag 或 digest；生产环境没有依赖不可预测的 `latest`。
- [ ] 端口、反向代理、网络和依赖服务的所有者明确。
- [ ] `.env`、密钥和证书未进入对话、日志或版本库。

## 数据与恢复

- [ ] 数据库、上传文件和命名卷已识别，且有保留期明确的备份。
- [ ] 已记录备份位置、恢复负责人和最后一次恢复演练时间。
- [ ] 升级前已保存 Compose/环境变量键名清单与当前镜像版本检查点。
- [ ] 变更计划没有使用 `down -v`、prune 或删除卷作为常规修复手段。

## 健康与值班

- [ ] 每个关键服务有 healthcheck 或业务探针；仅“容器 Running”不视为业务恢复。
- [ ] 告警按服务、环境和严重程度路由到正确负责人。
- [ ] Saki Watch 的冷却、频率和自动批准策略符合服务风险等级。
- [ ] 已定义失败时的回滚版本、验证步骤与人工升级路径。
